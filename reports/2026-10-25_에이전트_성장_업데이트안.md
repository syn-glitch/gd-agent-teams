## 0. 방식 — 헤르메스·하네스 엔지니어링을 우리 팀에 맞게

| 개념 | 뜻 (우리 말로) | 우리 팀에서 |
|---|---|---|
| **헤르메스식 학습 루프** | 에이전트가 일을 하며 겪은 실패·지적을 **스스로 기록 → 규칙·스킬로 증류 → 다음 일에 자동으로 적용 → 효과를 다시 확인**하는 닫힌 고리. 경험이 대화창에서 사라지지 않고 "다음 번의 기본값"이 된다 | 회고(이 문서) → 메모리·규칙·스킬 문서 갱신 → 다음 프로젝트 착수 보고서에 자동 포함 → 김감사가 지켜졌는지 확인 |
| **하네스 엔지니어링** | 모델을 더 똑똑하게 만드는 대신, 모델을 감싼 **환경(규칙·도구·체크·훅·데이터)**을 설계해 실수를 구조적으로 막는 것 (COMMON_HARNESS_INFRA.md 의 "실패 기반 개선 루프") | 배포 게이트, 착수 선언, 설계 질문 카드, 세션 종료 카드, 관제판 같은 "장치" |

**원칙**: 지적을 "다음엔 조심하겠습니다"로 끝내지 않는다. 지적 하나 = **장치 하나**(규칙 문장 · 체크리스트 칸 · 스킬 단계 · 훅 · 메모리) 로 바꾼다.

### 지적 → 장치 대응표 (이번 회고)
| 지적·문제 | 장치 | 위치 |
|---|---|---|
| 원본을 나중에 만듦, AI가 질문 안에서만 답함 | **설계 질문 카드 6** + **3회 규칙** | A-1, B-1, C-1 |
| 아티팩트 vs 잇다 로컬 서버 혼동 | **착수 선언 4줄** + **화면 대조** | B-2 |
| 배포 전 화면 증거 생략 | **배포 게이트 5단계** | B-3, E-2 |
| 영어 답변 | 한국어 출력 규칙(이미 반영) + 서브에이전트 결과 번역 의무 | A-4 |
| AI가 원문을 줄임 | **원문 보존 규칙** | A-5 |
| 시연 데이터를 개발자가 DB에서 지움 | 설계 질문 카드 ⑤ + 테스트 계정 기본 제공 | A-1 |
| QA 판단이 갈림 | **판정 조정 단계** | D-2 |
| 도구 오류(apply_migration) | **마이그레이션 적용 절차** | B-4 |
| 여러 프로젝트 운영 부담 | **세션 종료 카드** + **프로젝트 관제판** + WIP 상한 | A-6, E-1 |

## A. COMMON_RULES.md 추가안 (전 팀 공통)

```markdown
### [신설] 설계 질문 카드 (기획·착수 필수) — 2026-10-25 슈퍼샘플 회고
새 기능·새 서비스를 기획하거나 착수할 때, 요청 범위 밖이라도 아래 6가지를 먼저 묻고 이해보고서에 답을 적는다.
비전공 의뢰자에게는 "왜 지금 정해야 하는지"를 한 줄로 붙인다. 해당 없으면 "해당 없음 — 이유"를 적는다.
1. 원본·버전: 복사·재사용되는 것의 기준판은? 버전은 어떻게 쌓고, 누가 원본을 바꾸며, 어떻게 되돌리나?
2. 범위: 같은 과정·프로젝트 안에서 사람·데이터가 나뉘는 단위는? (회차·반·팀·기수)
3. 보호: 누가 만들고·고치고·지울 수 있나? 지우면 무엇이 같이 사라지나?
4. 동시성·경계: 두 사람이 동시에 누르면? 다른 그룹 사람이 누르면?
5. 테스트·시연 데이터: 시험 계정과 실제 사용자를 어떻게 구분하고, 시연 뒤 누가 어떻게 지우나?
6. 서버 규칙: 화면에서 숨기거나 막은 규칙을 서버(DB)도 똑같이 지키나?

### [신설] 3회 규칙
같은 화면·같은 데이터 영역에 대한 수정 요청이 세 번째로 들어오면, 바로 고치지 말고
"구조 점검 제안"(지금 구조의 한계 + 설계 질문 카드 중 해당 항목 + 추천안)을 먼저 낸다.

### [신설] 세션 종료 카드
작업 한 덩어리를 마치면 모든 에이전트는 아래 5줄을 남긴다(관제판·카톡 동시).
① 끝난 것 ② 확인할 링크·캡처(최대 3, 전체 경로) ③ 대표 승인 대기 ④ 다음 할 일 ⑤ 사용 토큰·남은 한도(아는 범위)

### [강화] 출력 언어
서브에이전트·도구가 영어로 돌려준 결과도 대표에게 전달할 때는 반드시 한국어로 옮긴다.

### [신설] 원문 보존
대표·강사가 준 원문(시트·문서·목록)을 가져올 때 항목 수와 순서를 줄이거나 합치지 않는다.
다듬는 것은 문장 표현까지. 줄여야 한다고 판단되면 먼저 묻는다.

### [신설] 운영 지시 대조
"NNN 적용해 / 배포해" 같은 운영 변경 지시는 대기 목록과 대조해 무엇을 적용하는지 한 줄로 밝히고 진행한다.
(예: "025는 이미 적용 — 대기 중인 026을 적용합니다")
```

## B. jarvis-dev_DESIGN.md (자비스) 추가안

**B-1. 이해보고서 템플릿에 칸 추가**
```markdown
## 설계 질문 카드 (COMMON_RULES) — 이번 요청과 관련된 항목만, 나머지는 "해당 없음"
## 이 요청 뒤에 반드시 따라올 것 (AI 제안) — 대표가 묻지 않았지만 곧 필요해질 기능·구조 1~3개
```
→ "질문 안에서만 답하기"를 막는 칸. 예: "핑보드 가져오기" 요청 → "가져오는 대상의 원본·버전 관리가 곧 필요합니다(추천: 보관함 + 원본 지정)".

**B-2. 착수 선언 4줄 (기준 화면 고정)**
```markdown
- 기준 문서: <아티팩트 URL> v<번호> (이 화면이 정답)
- 저장소·브랜치: <경로>
- 확인 주소: 데모 http://localhost:<고정 포트> / 운영 <URL>
- 같은 저장소의 다른 제품 화면: <예: 잇다 설치 /steps — 이번 범위 아님>
```
대표에게 화면을 보여 주기 전, 기준 문서의 해당 화면과 나란히 놓고 다른 점을 한 줄로 적는다(화면 대조).

**B-3. 배포 게이트 5단계** (메모리 `deploy-needs-local-screenshot` 을 절차로)
1. 데모 캡처(PC·휴대폰) + 전체 경로 + 한 줄 설명 → 2. 대표 확인 → 3. 마이그레이션 적용(있으면) → 4. 배포 → 5. 운영 확인(로그인 없는 확인 + 가능하면 테스트 계정으로 거부·정상 1건씩) 과 "운영에서 못 본 것" 명시

**B-4. 마이그레이션 적용 절차**
- 적용 전 대상 객체가 없음을 조회로 확인 → `apply_migration` → 실패 시 적용 여부 재조회 → 같은 SQL을 한 거래로 `execute_sql` + `supabase_migrations.schema_migrations` 기록 → 객체·권한 재조회.
- 마이그레이션마다 되돌리기 파일·테스트 하네스·데모 목록 동시 갱신(이번 프로젝트에서 지킨 방식 그대로).

**B-5. 테스트 계정 기본 제공**: 사용자 역할이 있는 서비스는 첫 배포 때 역할별 테스트 계정과 "테스트 표시·정리" 기능을 같이 낸다.

| 적대적 QA | 권한 우회·다른 그룹·직접 API 호출·입력 공격 | 요청·응답 증거 |
| 동시성 QA | 두 사람이 같은 작업 동시 실행, 연속 클릭 | 재현 절차·DB 상태 |

**D-2. 판정 조정 단계**: 전문가끼리 판단이 갈리면 팀장이 근거(코드·정책·운영 데이터)를 직접 확인해 범위를 좁히고, 보고서에 "판정 조정" 칸으로 남긴다.
**D-3. 병렬 QA 운영 규칙**: 브라우저는 한 명만, 나머지는 curl·쿠키. 전문가마다 계정을 나눠 기록이 섞이지 않게. 운영은 읽기·거부 확인만.
**D-4. 회고 증류 확인**: 다음 QA 때 "지난 회고의 장치가 지켜졌는가"(설계 질문 카드 칸 존재, 배포 게이트 캡처 첨부 등)를 체크 항목으로.

## E. 새 장치 (스킬·관제판·훅)

**E-1. 프로젝트 관제판 (추천 1순위)**
- 아티팩트 1개(DB 기능): 프로젝트별 행 — 상태 · 마지막 결과 링크·캡처 · **승인 대기** · 다음 할 일 · 주간 토큰 · 마지막 갱신.
- 모든 팀 스킬의 마지막 단계: "세션 종료 카드를 관제판에 기록". 기획사수·뉴스레터 관제판 방식을 재사용.
- WIP 상한(활성 2 + 백그라운드 1)과 승인 시간(하루 2~3회)을 관제판 위에 표시.

**E-2. 스킬 `/배포게이트`** (자비스 하위): B-3 다섯 단계를 순서대로 실행하고, 캡처가 없으면 배포 단계로 넘어가지 않는다.

**E-3. 스킬 `/설계질문`** (벙커·자비스 공용): 요청 한 줄을 받으면 설계 질문 카드 6개에 대해 "해당/해당 없음 + 추천안"을 아티팩트 칸으로 채워 돌려준다.

**E-4. 스킬 `/회고증류`**: 세션 기록(대표 지시 목록)을 읽어 "지적 → 장치" 표를 만들고, 메모리·규칙·스킬 변경안을 이 문서 형식으로 낸다(이번 회고를 만든 과정의 자동화).

**E-5. 하네스 훅 후보** (settings.json, 대표 승인 후)
- 배포 명령(`vercel deploy --prod`) 실행 전: 최근 30분 안의 데모 캡처 파일이 scratchpad 에 있는지 확인, 없으면 경고.
- 마이그레이션 적용 도구 호출 전: 같은 번호의 rollback 파일이 있는지 확인.
